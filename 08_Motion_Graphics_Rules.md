# Motion design and transitions

## Motion philosophy
Produce believable, purposeful motion with Adobe After Effects-level polish. Text, shapes, model and interface should have layered animation, not the appearance of still images placed sequentially.

## Allowed motion vocabulary
- Camera push through geometry -> reveal BDESIGNER modelling stage.
- Draw-on construction lines, measured dims and grid reveals.
- Wireframe-to-material shift where actual model imagery supports it.
- Controlled typography kinetic builds: mask reveal, tracking, word emphasis.
- Morph a foundation outline into the next stage's model.
- Tight animated connectors: model -> quantity number -> BOQ row -> PDF page.
- Match cuts on construction edges or viewport landmarks.
- Gentle 3D parallax, restrained UI panels sliding on purposeful beats.
- Small HUD/data highlights, never so many that model is obscured.

## Rhythm
Opening hook in first seconds; 1 message per scene; faster build during feature montage; slow enough for readable product proof; resolve cleanly on CTA or tutorial result.

## Editing requirements
- Smooth acceleration/easing; no spontaneous shaky camera.
- Transitions should be spatially consistent with the hero geometry.
- Animate from layer assets/screens that are visually matched in camera, shadows, material and palette.
- Preserve screen continuity: same logo size, counter location, headline grid and caption lane.
- Keep model legible, especially plan/section views and dimensions.

## Practical tooling
Generated images can provide still concepts or style frames. Animate them using Runway/Magnific/other video tools or an editor according to tool capabilities, but **do not assume** a still image has real working UI. Supply separate IMAGE and ANIMATION prompts for each scene; final proof shots use SketchUp captures.

## Quality rejection test
If it feels like "picture 1 -> picture 2 -> picture 3" or transitions glitch / distort the model, revise rather than approve.
